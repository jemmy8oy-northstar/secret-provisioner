# Fixtures

These are **the real planner's output**, not a drawing of it.

`execute.js` is one side of a seam that spans two repositories: the plan it
consumes is produced by
[`oke-fleet:scripts/plan-secrets.mjs`](https://github.com/jemmy8oy-northstar/oke-fleet/blob/dev/scripts/plan-secrets.mjs).
A hand-written plan fixture would test my memory of the plan's shape, which is
the thing most likely to be wrong — and it would go on passing after the planner
changed. So these are generated by running the planner.

Generated from `oke-fleet` commit `34c7d8c` (branch `feat/secret-plan`,
[oke-fleet#9](https://github.com/jemmy8oy-northstar/oke-fleet/pull/9)).

| file | what it is |
| --- | --- |
| `declarations.json` | what `validateSecrets('secrets', 'config')` returned — the live `oke-fleet/secrets/*.json` |
| `empty-estate.plan.json` | the plan for an estate with nothing in it: 2 roles, 2 databases, 2 `create-secret`, 3 `blocked` |
| `partial-estate.plan.json` | an estate where `around-the-world-secrets` already holds 5 keys: 1 `patch-secret-key`, 1 `unmanaged`, 5 `noop` |
| `distinct-role-and-database.json` | **synthetic, and deliberately so** — both live declarations name `role === database`, so no fixture drawn from the real estate can tell the two fields apart. Carries its own `declarations` alongside its `plan`. |

## Regenerating

With `oke-fleet` checked out beside this repo:

```sh
node --input-type=module -e "
process.chdir('../oke-fleet');
const { planSecrets } = await import('../oke-fleet/scripts/plan-secrets.mjs');
const { validateSecrets } = await import('../oke-fleet/scripts/validate-secrets.mjs');
const { writeFileSync } = await import('node:fs');
const { errors, declarations } = validateSecrets('secrets', 'config');
if (errors.length) throw new Error(errors.join('\n'));

const empty = { namespaces: [...new Set(declarations.map((d) => d.namespace))], secrets: {}, postgres: { roles: [], databases: [] } };
const partial = {
  namespaces: ['balenthiran'],
  secrets: {
    'balenthiran/around-the-world-secrets': ['ConnectionStrings__DefaultConnection', 'Admin__Key', 'PhotoStorage__AccessKeyId', 'PhotoStorage__SecretAccessKey', 'LegacyMigrationToken'],
    'balenthiran/macro-metrics-secrets': ['FRED_API_KEY'],
  },
  postgres: { roles: ['aroundtheworld'], databases: ['aroundtheworld'] },
};
const out = '../secret-provisioner/src/fixtures/';
writeFileSync(out + 'declarations.json', JSON.stringify(declarations, null, 2) + '\n');
writeFileSync(out + 'empty-estate.plan.json', JSON.stringify(planSecrets(declarations, empty), null, 2) + '\n');
writeFileSync(out + 'partial-estate.plan.json', JSON.stringify(planSecrets(declarations, partial), null, 2) + '\n');
"
```

**If a regenerated fixture changes, that is the news** — the planner's output
shape moved, and the tests here are the only thing on this side of the seam that
would ever say so. Read the diff before committing it.
